# Sổ Tự Học V8.7.1 Full Stack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce one verified V8.7.1 full-stack source/release package with the current Vue frontend, complete Supabase Edge Function source, safe alternate database install/upgrade paths, verification SQL, deployment ZIPs, and checksums.

**Architecture:** Preserve the V8.7.1 Vue frontend as-is, import the complete verified V8.4.0 Supabase backend, apply only the later reusable backend changes, and replace the AI Edge Function with the V8.7.1 implementation. Database installation and current-system upgrade are separate mutually exclusive paths that converge on the same V8.7.1 verifier.

**Tech Stack:** Vue 3, TypeScript, Vite, Supabase/PostgreSQL/RLS/RPC, Supabase Edge Functions (Deno/TypeScript), Node test runner, Vitest where dependencies are available.

**Spec:** `docs/superpowers/specs/2026-08-26-v871-full-stack-design.md`

## Global Constraints
- Keep frontend package version `8.7.1`.
- Do not include a real `config.js`, Supabase service-role/secret key, Groq key, or other server secret.
- Do not replay the one-time `10A1 -> 7A9` repair in the generic upgrade path.
- Keep exactly one root admin and preserve the existing bootstrap/transfer maintenance functions.
- AI automation remains Groq-only; no keyword/rule approval fallback is introduced.
- Generic upgrade must be safe to run again on an already-upgraded V8.4.x-family database.
- Fresh-install path must explicitly state it requires the compatible core Sổ Tự Học baseline; do not claim empty-project support.
